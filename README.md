# 票务占座过期与出票一致性

使用者：演出票务渠道对账员。回放多渠道占座付款出票日志，找出售卖冲突与超时悬单。

核心规则：占座租约使用事件时间，付款时刻必须早于到期点，同版本冲突拒绝，释放后旧支付不能复活席位。

## 启动

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
docker compose config --quiet
```

浏览器访问 http://localhost:18204 。首页已装载脏样例，可编辑CSV与参数后运行，也可上传文件。八个导航分别对应业务步骤。

## 模块

- M1 渠道接收：接收各渠道事件，入口 `/m/1`、`GET/POST /api/m1`。
- M2 座席映射：映射座席并裁决版本，入口 `/m/2`、`GET/POST /api/m2`。
- M3 租约回放：回放占座释放租约，入口 `/m/3`、`GET/POST /api/m3`。
- M4 支付归属：按有效租约归属支付，入口 `/m/4`、`GET/POST /api/m4`。
- M5 出票核验：检查支付及票号一致，入口 `/m/5`、`GET/POST /api/m5`。
- M6 渠道对账：核对渠道金额与悬单，入口 `/m/6`、`GET/POST /api/m6`。
- M7 补传复核：补传回放和版本复核，入口 `/m/7`、`GET/POST /api/m7`。
- M8 票号盘存：号段连号盘存、缺报冻结与补回执对账，入口 `/m/8`、`GET/POST /api/m8`。

## 票号盘存（M8）

预印票纸按连号发放，打印机可能先出纸后丢失回执，渠道再晚到补来打印记录。M8 以独立盘存 CSV（`sample_data/inventory.csv`，字段见数据字典）累积盘存：

- 票号状态沿 `可发放 → 已占用 → 待核实 → 已售` 只升不降；缺报票号冻结在待核实，绝不按未用重发，已确认（已售）票号不能重新变成可发放（规则层与 SQLite 触发器双重守卫）。
- 临售申领只取号段内最小的可发放连号；业务参考（ref）去重，同一盘存重跑复用批次且不重复占用。
- 补回执后的票款对账与占用在同一事务更新：有效支付减已确认纸票为悬单，待核实金额单列；纸票连号与电子票号为两套编号，按渠道、金额、出纸时点交叉核销。
- 号段重叠、跨渠道打印、越界票号、超量申领、重复回执、状态回退全部带原始行号与原因码进入隔离，证据见 `/api/m8/evidence.csv`。

## 演示与复核

1. 运行默认样例，核查隔离原因与业务合计。
2. 修改CSV单元格或参数并重跑，保留行号与输入摘要。
3. 在最后一步复核，旧版本提交返回409。
4. 证据CSV包含采信行和隔离行，重跑相同内容复用批次。

## 数据与目录

`app/modules/` 按业务切分；`sample_data/` 为UTF-8 BOM、GB18030及干净/脏样例，`inventory.csv` 与 `inventory_late.csv` 为票号盘存及迟到补回执样例；`tests/` 含规则与端到端测试。SQLite保存运行与复核（`runs` 表）及盘存占用（`inv_*` 表），命名卷records保留重启后的记录。若需从头开始，可先停止服务并在确认不再需要记录后删除该项目records卷。

## 定义与边界

单场演出16个座席，不处理退票退款。占座租约释放或到期后，迟到付款不能恢复租约；出票必须已有有效付款且座席不可重复出票。

详细字段、计算定义与原因码见 `docs/DATA-DICTIONARY.md`，回归证据见 `docs/DEPTH.md`。
